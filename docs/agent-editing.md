# Agent 修改既有凭据

用户授权目标：让 agent 修改已有凭据时不再依赖容易超时的界面控制，同时保持明文不进入聊天。

## 契约

新增模型可调用的 `update_secret`；原有模型工具与 app-only 工具保持兼容。
参数包含目标 `secret_id`、`expected_revision`、可选的 `changes`、`field_refs`、`remove_fields`。

- `changes` 只允许 name、kind、provider、account、environment、tags、notes。省略/null 保留，空文本/列表清空相应元数据。
- `field_refs` 的键为目标凭据字段，值为已有来源的 ID、revision、field 及可选 json_path。json_path 只支持逐层对象键，且结果必须是字符串。
- 同类型修改保留其他值；类型变更从空字段集合开始，由引用明确组成新的完整字段集合。
- `remove_fields` 只能移除目标已有字段；不能与引用目标重叠，不能让必填字段缺失。
- 不接受明文 values，不允许新建、删除、恢复；不更改来源记录。输入模型拒绝未知的元数据字段和引用属性，原生入口再次校验。
- 在现有本机存储锁内检查目标和来源版本，解析所有引用，完整验证后只写目标一次。失败不能留下部分修改。此锁不是跨设备 iCloud CAS。
- 返回仅包含元数据。密钥值、JSON 解析内容和原始异常不得进入输出。

## 验证

使用独立 TESTING 内存存储，不读写真实凭据，覆盖：

- 元数据编辑保持 ID、所有原值及未指定元数据。
- JSON Token 原位转换数据库记录，字段提取只发生在原生组件。
- 跨记录引用、可选字段移除，来源记录保持不变。
- 目标版本冲突、来源更新/回收/删除、路径不存在、非字符串、未知参数、必填字段移除及重叠修改均失败，不产生部分写入。
- 不存在的目标不会被创建，回收站目标不会被恢复。
- MCP 真实调用路径公开 update_secret，输入结构无 values，结果无合成凭据值。

代码提交、安装和发现新工具不代表当前聊天已切换到新 MCP 进程。真实库无需为验证本功能而改动；真实写入仍按用户具体任务执行。

## 真实启动发现的缓存问题

首轮源码测试通过，但正式启动未发现新增工具。定位到所有版本复用同一个 venv，
且 uv 默认缓存键不包含 Python 源码和打包界面，因而同一路径启动可复用旧 wheel。
修复为按插件绝对路径哈希隔离 venv，并将 Python 源码和内嵌 HTML 纳入 uv 缓存键。
不删除旧环境、不热替换现有进程。验证使用实际安装入口，检查工具列表、资源模式及
原生 update 分发对不存在目标的拒绝；不得仅以 pytest 的源码导入路径通过作为发布证据。

- 当前聊天的旧进程不自动获得新工具；新进程的安装入口已通过验证，但当前聊天热切换未验证。
